# FTC 반출 자동 마스킹 — 연계 방안 검토 및 로드맵

> 대상: `data_masking_program` (엑셀 개인정보 마스킹) ↔ 사내 **FTC 자료전송시스템(휴네시온)**
> 작성일: 2026-07-02
> 목적: "업무망 → 인터넷망 파일 반출 시 **자동 마스킹**" 요구의 실현 가능성을 근거와 함께 정리하고,
>       규제(국정원 N2SF·개인정보보호법)에 맞는 **단기 대책 + 장기 로드맵**을 제시한다.

---

## 0. 한 줄 결론

> **"FTC 실행파일을 뜯어고쳐 마스킹을 넣는 것"은 불가(하면 안 됨)**이지만,
> **"반출 시 자동 마스킹"이라는 목표 자체는 합법적으로 달성 가능**하다.
> 다만 진짜 "전송 순간 자동·강제"는 **서버측/벤더 연계**가 있어야 하고,
> 그 접근이 확보되기 전까지는 **엔드포인트 원클릭 마스킹(단기 대책)**으로 유도한다.

---

## 1. 현황 — 지금 이 FTC가 무엇인가 (근거)

사내 FTC는 **휴네시온(Hunesion)의 상용 망연계 자료전송 솔루션**이다. 자체 개발물이 아니다.

| 근거 파일 | 무엇을 말해주나 |
|---|---|
| `FtcGnNacAuth.exe`, `Hunesion_ToolBar.dll` | **휴네시온** 브랜드 바이너리 (GnNac = 휴네시온 NAC 인증) |
| `FTC_Client_Main.exe` (약 7MB 단일 실행파일) | 소스 비공개 컴파일 바이너리 + DevExpress 상용 UI 라이브러리 |
| `conf/ftc_save.ini`, `log/FTC URL_*.log` | 설정·로그가 **전부 암호화**(`kZXUpjsDRg/...`) — 내부가 의도적으로 잠긴 하드닝 제품 |
| `conf/ftc_message.ini` | 전송 흐름: `in.context.string = 파일전송[FTC]->인터넷망PC` / `out.context.string = 파일전송[FTC]->업무망PC` → **중계서버 경유 양방향 망간 전송** |
| `SharpShell.dll`, `Hunesion_ToolBar.dll` | FTC의 우클릭 메뉴가 **COM 셸 확장** 방식으로 구현돼 있음(참고) |

**실제 사용 흐름(담당자 확인):** 사용자가 FTC 클라이언트에서 "보내기"를 눌러 **임의의 파일/폴더를 직접 지정**해 반출한다. 전용 "전송대기함" 폴더 같은 것은 없다. 승인은 **사전 승인**과 **사후 승인**이 있는데, 실무에서는 보통 **사후 승인**(먼저 반출하고 나중에 결재)을 쓴다.

## 2. 왜 "FTC에 직접 구현"이 막히나 — 3중 차단 + 규제 공백

### 2-1. 세 갈래 길목이 모두 닫혀 있음

| 길목 | 상태 | 근거 |
|---|---|---|
| ① FTC 클라이언트 바이너리 개조 | ❌ 불가 | 휴네시온 상용 저작물. 역공학·바이너리 패치·후킹 주입 = **저작권법 위반 + 벤더 계약 파기 + 보안인증 파기**. 암호화된 클로즈드 바이너리라 기술적으로도 불안정(업데이트마다 깨짐) |
| ② 중계서버 필터 연동 | ❌ 접근 불가(현재) | KEPCO가 FTC 서버측에 접근 어려움 |
| ③ 벤더(휴네시온) 공식 연계 | ❌ 채널 없음(현재) | 유지보수/기술문의 채널 미확보 |

> ⚠️ **가정(검증 필요):** 이 제품은 국정원 보안적합성 검증(CC/보안기능확인서)을 받은 구성으로 도입됐을 가능성이 높다(공기업 망연계 필수). 인증 구성에 **미인증 임의 코드**를 끼우면 개인정보를 보호하려다 **오히려 N2SF/보안인증 위반**이 된다. → **도입 부서의 보안성 검토서/CC인증서로 확인할 것.**

### 2-2. "사후 승인"이 만드는 규제 공백 (핵심 리스크)

사후 승인은 **파일을 먼저 반출하고 나중에 결재**하는 구조다. 따라서 설령 결재 시점에 검사를 넣더라도 **개인정보는 이미 인터넷망으로 나간 뒤**다. 검사 시점이 늦다.

- 이는 단순 기술 문제가 아니라 **개인정보보호법 제29조(안전조치의무)·N2SF 전송통제** 관점의 **구조적 취약점**이다.
- 이 사실 자체가, 장기적으로 **서버/벤더 접근을 확보해야 하는 강력한 설득 근거**가 된다(6장).

### 2-3. 엔드포인트에서 "임의 파일 실시간 가로채기"도 불가

사용자가 아무 파일이나 직접 고르므로, 이를 실시간 가로채려면 **파일시스템 필터 드라이버/후킹 에이전트**를 PC에 심어야 한다. 이는 침습적이고 **인증 구성에 미인증 커널/후킹 주입** → 역시 정책 위반 방향이다. 채택하지 않는다.

## 3. 돌파구 — 正反合

- **正 (하고 싶은 것):** 반출 순간 자동 마스킹
- **反 (제약):** 위 3중 차단 + 사후 승인이 마지막 게이트마저 무력화
- **合 (합법적 혁신):** *FTC 바이너리·서버는 건드리지 않고, 전송 "동선"에 마스킹 단계를 합법적으로 끼운다.*
  - 아이디어(자동 마스킹)는 살리고, 표현(벤더 코드)은 건드리지 않는 clean 경로.
  - "전송 순간"을 못 잡으면 → **전송 직전 동선에 밀착**시켜 원클릭으로 만들고, **정책·감사로 미마스킹 반출을 억제**한다.

## 4. 로드맵 (2단계)

### 4-A. 단기 대책 — 엔드포인트 원클릭 마스킹 (지금 적용 가능, 인증 무관) ✅ 구현됨

탐색기에서 엑셀 파일을 **우클릭 → "개인정보 마스킹본 만들기"** → 원본 옆에 `파일명_마스킹.xlsx` 생성 → 사용자는 그 마스킹본을 FTC로 반출.

**구성 파일 (이 저장소):**
| 파일 | 역할 |
|---|---|
| `mask_cli.py` | 파일 하나를 headless로 마스킹(원클릭 실행 대상). 공용 엔진(`masking_engine`) 재사용 |
| `register_context_menu.py` | 우클릭 메뉴 **등록** (레지스트리 기록) |
| `unregister_context_menu.py` | 우클릭 메뉴 **해제** |
| `uninstall.py` | **전체 원복** (레지스트리 + 데이터) — 8장 |

**동작 원리(설명가능):** Windows 탐색기는 우클릭 시 레지스트리를 읽어 메뉴를 그린다. 특정 확장자에 메뉴를 붙이려면 아래에 값을 심는다(7장 상세).

**설명가능·검증가능:** 처리 후 "무엇을 왜 몇 건 마스킹했는지" 요약 창을 띄우고, 결과 파일의 `[분류리포트]` 시트로 근거를 직접 확인할 수 있다. 처리 이력은 **메타데이터만**(셀 본문 제외) 감사로그(JSONL)에 남긴다 → `docs/사용이력_로깅_도입안.md` 원칙과 일관.

> ⚠️ **한계(정직하게):** 이것은 우클릭을 **유도**하는 것이지 **강제가 아니다.** 사용자가 우클릭 없이 원본을 바로 FTC에 넣으면 마스킹되지 않는다. 진짜 강제는 4-B가 필요하다. 이 한계를 이해하고 운영 정책(교육·점검)으로 보완할 것.

### 4-B. 장기 대책 — 서버측 필터 연계 (진짜 "전송 순간 자동·강제") ▶ 접근 확보 필요

사용자가 어느 폴더에서 고르든 모든 전송은 **업무망 → 중계서버 → 인터넷망**을 통과한다. 임의 파일 선택을 전부 잡을 수 있는 유일한 지점이 여기다.

- 휴네시온 계열 망연계 솔루션은 대개 **"전송 릴리스 전 콘텐츠 검사/필터 연동 인터페이스"**(CDR·DLP·백신 연동 훅)를 서버측에 제공한다. 여기에 우리 `masking_engine`을 필터로 등록하면 **통과 순간 자동 마스킹**이 된다.
- **선결 조건:** ① FTC 서버측 구성 접근 또는 ② 휴네시온 공식 연계 채널. → 2-2의 규제 공백을 근거로 보안팀·리더십에 확보를 요청(6장).
- **장점:** 진짜 전송 순간·우회 불가·인증 유지. **단점:** 벤더 협의·비용·기간.

## 5. 규제 근거

| 근거 | 요지 | 이 방안과의 관계 |
|---|---|---|
| 개인정보보호법 제29조(안전조치의무) + 표준 개인정보보호지침 | 개인정보 처리 시 안전조치 의무 | 망간 반출 시 **마스킹**은 정당한 안전조치 |
| 개인정보보호법 제28조의7 등(가명·익명처리) | 가명/익명 처리 인정 | 마스킹은 인정되는 처리 방식 |
| 국가 망 보안체계(N2SF) 보안가이드라인 (국정원) | 물리적 망분리 → 다중계층보안. **망간 전송 통제(암호화·필터링·로깅)** 요구 | 마스킹 필터·감사로그가 이 통제에 부합 |

> **단, 핵심:** 이 통제는 반드시 **"인증된 제품/구성"**으로 해야 한다. 그래서 4-B(서버/벤더 연계)가 정도(正道)이고, 4-A는 인증 경로를 건드리지 않는 **보완책**이다.

## 6. 의사결정 요청 (보안팀·리더십)

1. **단기(4-A) 승인:** 엔드포인트 원클릭 마스킹 도구를 현업에 배포할지? (인증 영향 없음, 언제든 원복 가능)
2. **장기(4-B) 추진:** 2-2의 **사후 승인 규제 공백**을 근거로, **FTC 서버측 접근 또는 휴네시온 공식 연계**를 추진할지?
3. **인증 확인:** 현 FTC가 CC/보안기능확인서 기반 구성인지 도입 부서에 확인(2-1 가정 검증).

## 7. 레지스트리 변경 사항 (중요 — 무엇을 건드리는가)

단기 대책(4-A)의 우클릭 메뉴는 **Windows 레지스트리**에 값을 심어 구현한다. 무엇을 건드리는지 투명하게 밝힌다.

**변경 위치 (HKEY_CURRENT_USER = 내 계정 전용, 관리자 권한 불필요):**
```
HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.xlsx\shell\FtcMaskExport
HKEY_CURRENT_USER\Software\Classes\SystemFileAssociations\.xls\shell\FtcMaskExport
    MUIVerb  = "개인정보 마스킹본 만들기"       (메뉴에 보이는 이름)
    Icon     = (아이콘 파일이 있으면)             (선택)
    \command
        (기본값) = "pythonw.exe" "mask_cli.py" "%1"   ("%1" = 우클릭한 파일 경로)
```

**안전성 근거:**
- `HKEY_CURRENT_USER` 아래라 **관리자 권한이 필요 없고**, 다른 사용자 계정·시스템 전역에 영향 없음.
- `SystemFileAssociations\.xlsx` 는 **확장자에만** 메뉴를 얹는 위치라, 엑셀의 파일연결(`Excel.Sheet.12`)·더블클릭 동작을 **건드리지 않는다.**
- 우리 키 이름은 `FtcMaskExport` 하나뿐 → 제거 시 이 키만 지우면 완전 원복.
- **다른 레지스트리 영역(HKLM, 시스템 서비스, 시작프로그램 등)은 일절 변경하지 않는다.**

**검증 방법(사용자가 직접 확인):**
```
reg query "HKCU\Software\Classes\SystemFileAssociations\.xlsx\shell\FtcMaskExport\command"
```
또는 `regedit`에서 위 경로를 직접 열람.

## 8. 전체 원복(제거) 절차 — "쓰지 말라" 지시 대응

회사에서 사용 중지를 지시해도 **흔적 없이 원복**할 수 있다.

### 8-1. 레지스트리 + 데이터 한 번에 (권장)
```
python uninstall.py                     # 레지스트리 제거 + 데이터는 보존(안전 기본값)
python uninstall.py --purge-data --yes  # 데이터 폴더(감사로그 포함)까지 삭제 — 주의
```

### 8-2. 우클릭 메뉴만 제거
```
python unregister_context_menu.py
```

### 8-3. 원복 시 주의점 (설명가능·정직)
| 대상 | 처리 | 이유 |
|---|---|---|
| 레지스트리 우클릭 메뉴 | 항상 제거 | HKCU의 `FtcMaskExport` 키만 삭제 → 완전 원복 |
| **감사로그** (`감사로그/*.jsonl`) | **기본 보존** | 개인정보보호법 안전조치 **증빙**. 함부로 지우면 안 됨. `--purge-data --yes` 로만 삭제 |
| 감시폴더 (`마스킹_감시폴더`) | `--purge-data` 시 삭제 | 트레이 앱이 만든 작업 폴더 |
| 원본 옆 `_마스킹.xlsx` 결과물 | 자동 삭제 안 함 | 사용자 파일. 여기저기 흩어져 있어 자동 수거가 위험 → 사용자가 직접 판단 |
| 트레이 상주앱(설치형) | 제어판에서 제거 | Inno Setup(`installer.iss`) 설치본은 [제어판 > 프로그램 제거]로 |
| 소스 코드(이 폴더) | 그대로 둠 | 필요 시 폴더째 삭제 |

## 9. 확인이 필요한 사항 (요약)

1. 현 FTC가 **CC/보안기능확인서 기반 구성**인지 (2-1 가정 검증)
2. **서버측 접근** 또는 **휴네시온 공식 연계 채널** 확보 가능 여부 (4-B 선결)
3. 단기 대책(4-A) **현업 배포 승인** 여부
4. 감사로그 **보관 기간·보관 위치** 정책 (`docs/사용이력_로깅_도입안.md` 부록과 연계)
