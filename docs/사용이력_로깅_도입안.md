# 사용 이력(누가 사용했는지) 로깅 시스템 도입안

> 대상 프로젝트: `data_masking_program` (N2SF 엑셀 마스킹 웹서버)
> 작성일: 2026-06-17
> 목적: **"누가 / 언제 / 어떤 파일을 / 무엇을 했는지"** 를 서버에 기록하여 사용 이력·감사(audit) 추적이 가능하도록 한다.

---

## 1. 배경 — 왜 필요한가

현재 `web/app.py`는 같은 망의 여러 PC가 브라우저로 접속해 엑셀을 업로드·마스킹하는 구조다. 그런데 **사용 기록이 전혀 남지 않는다.**

- `/analyze`, `/mask` 라우트 어디에도 로그를 남기는 코드가 없다.
- 처리 후 임시 파일은 즉시 삭제된다(`os.remove(path)`) → 사후에 "누가 썼는지" 추적할 단서가 없다.
- 개인정보(이름·전화·주민번호 등)를 다루는 도구이므로, **누가 어떤 파일을 마스킹했는지** 자체가 보안·감사 관점에서 중요한 기록이다.

> ⚠️ 핵심 원칙: **로그에는 "행위 메타데이터"만 남기고, 엑셀의 실제 셀 값(개인정보)은 절대 기록하지 않는다.** 로그 파일이 또 다른 유출 지점이 되면 안 된다.

---

## 2. 무엇을 기록할 것인가 (로그 필드 설계)

| 필드 | 설명 | 예시 | 비고 |
|------|------|------|------|
| `ts` | 발생 시각(ISO 8601) | `2026-06-17T14:03:21+09:00` | 서버 시각 |
| `event` | 행위 종류 | `analyze` / `mask` / `error` | |
| `user` | 사용자명(입력값) | `홍길동` / `(미입력)` | 4장 식별 방식 참고 |
| `client_ip` | 접속 PC IP | `10.20.1.45` | `request.remote_addr` |
| `hostname` | 접속 PC 호스트명 | `PC-AHN-01` | 역방향 조회(선택) |
| `req_id` | 요청 식별자 | `a1b2…` (32hex) | analyze→mask 연결용 |
| `filename` | 원본 파일명 | `직원명부.xlsx` | **파일 내용은 X** |
| `rows` | 행 수 | `1240` | analyze 시 |
| `cols_total` | 전체 컬럼 수 | `12` | analyze 시 |
| `cols_c` / `cols_s` | C/S 등급 컬럼 수 | `2` / `5` | analyze 시 |
| `selected_cnt` | 마스킹 선택 컬럼 수 | `4` | mask 시 |
| `status` | 처리 결과 | `ok` / `error` | |
| `detail` | 에러 메시지 등 | `파일을 읽을 수 없습니다` | 실패 시 |

> 컬럼명(`이름`, `전화` 등)은 식별 메타데이터로 봐서 기록해도 무방하나, **셀의 실제 값은 기록 금지**.

## 3. 저장 방식 — 무엇으로 남길까

| 방식 | 장점 | 단점 | 추천 |
|------|------|------|------|
| **JSONL** (한 줄 1건, append) | 구현 단순, 손실 위험 적음, 파싱 쉬움 | 사람이 바로 읽기 불편 | ✅ **1순위** |
| CSV | 엑셀로 바로 열람 | 따옴표/줄바꿈 처리 까다로움 | 보조(내보내기용) |
| SQLite | 조회·필터·집계 강력 | 도입 비용·잠금 이슈 | 이력이 많아지면 전환 |

**권장안:** 일자별 JSONL 파일(`logs/usage-2026-06-17.jsonl`)에 한 줄씩 append. 필요 시 CSV로 내보내 엑셀로 본다. 이력이 커지면 SQLite로 이관.

- 저장 경로: 프로젝트 내 `web/logs/` (또는 운영 정책상 별도 보안 폴더)
- `.gitignore`에 `logs/` 추가 (이력에 파일명 등이 들어가므로 깃에 올리지 않음)
- 보관 기간 정책 수립 권장(예: 1년 후 자동 삭제/분리 보관)

## 4. "누가" 를 어떻게 식별할까 (가장 중요한 결정 포인트)

이 서버는 **로그인/인증이 없다.** 따라서 식별 방법을 정해야 한다. 난이도·정확도 순으로 3가지 옵션:

### 옵션 A — IP 주소만 (가장 간단, 코드만 추가)
- `request.remote_addr`로 접속 PC IP를 자동 기록.
- 장점: 프론트엔드 변경 불필요, 즉시 적용 가능.
- 단점: "IP=사람"이 아니다. DHCP 환경이면 매핑이 흔들림.
- **사번/이름 ↔ IP(또는 호스트명) 매핑표**(`users.csv`)를 두면 사후 식별 가능.

### 옵션 B — 사용자명 입력칸 추가 (권장 절충안) ✅
- 업로드 화면에 "이름/사번" 입력칸 1개 추가 → 브라우저 `localStorage`에 기억(매번 입력 X).
- `/analyze`·`/mask` 요청 시 같이 전송 → 로그의 `user` 필드에 저장.
- 장점: 사람 단위 식별 가능, 구현 부담 작음.
- 단점: 자율 입력이라 위·변조 가능(IP와 함께 남기면 교차검증 됨).

### 옵션 C — 사내 인증 연동 (가장 정확, 비용 큼)
- 윈도우 도메인 계정(AD/Kerberos) 또는 사내 SSO 연동.
- 망분리/운영 환경에 따라 도입 난이도가 크다. **추후 과제**로 분리 권장.

> **추천 시작점: 옵션 B (사용자명 입력) + 옵션 A(IP/호스트명 동시 기록).**
> 입력값(사람) + IP(교차검증) 둘 다 남기면 실무상 충분하다.

## 5. 적용 위치 — 기존 코드 어디를 건드리나

기존 로직은 그대로 두고 **로깅만 얹는다.** 변경 최소화.

1. 신규 파일 `web/usage_logger.py` 추가 (로깅 유틸, 아래 6장).
2. `web/app.py`의 `/analyze`, `/mask` 끝부분에 `log_event(...)` 호출 1~2줄 추가.
3. (옵션 B 채택 시) `templates/index.html`에 사용자명 입력칸 + fetch에 값 동봉.
4. `web/requirements.txt` 변경 없음(표준 라이브러리만 사용).
5. `.gitignore`에 `web/logs/` 추가.

## 6. 구현 예시 코드 (그대로 적용 가능)

### 6-1. `web/usage_logger.py` (신규)

```python
"""사용 이력 로깅 — 행위 메타데이터만 JSONL로 append. (개인정보 본문은 기록 안 함)"""
import os
import json
import socket
from datetime import datetime, timezone, timedelta

KST = timezone(timedelta(hours=9))
LOG_DIR = os.path.join(os.path.dirname(os.path.abspath(__file__)), "logs")
os.makedirs(LOG_DIR, exist_ok=True)


def _hostname(ip):
    """IP → 호스트명 역방향 조회(실패해도 무시)."""
    try:
        return socket.gethostbyaddr(ip)[0]
    except Exception:
        return ""


def log_event(event, *, user="", client_ip="", req_id="", filename="",
              status="ok", detail="", **extra):
    rec = {
        "ts": datetime.now(KST).isoformat(timespec="seconds"),
        "event": event,
        "user": (user or "(미입력)").strip(),
        "client_ip": client_ip,
        "hostname": _hostname(client_ip) if client_ip else "",
        "req_id": req_id,
        "filename": filename,
        "status": status,
        "detail": detail,
    }
    rec.update(extra)  # rows, cols_total, cols_c, cols_s, selected_cnt 등
    day = datetime.now(KST).strftime("%Y-%m-%d")
    path = os.path.join(LOG_DIR, f"usage-{day}.jsonl")
    with open(path, "a", encoding="utf-8") as fp:
        fp.write(json.dumps(rec, ensure_ascii=False) + "\n")
```

### 6-2. `web/app.py` 적용 (변경 지점만)

```python
from usage_logger import log_event   # 상단 import 추가

# /analyze 마지막 return 직전:
log_event("analyze",
          user=request.form.get("user", ""),
          client_ip=request.remote_addr,
          req_id=token,
          filename=f.filename,
          rows=len(df), cols_total=len(columns), cols_c=c_cnt, cols_s=s_cnt)

# /mask 처리 성공 후(send_file 직전):
log_event("mask",
          user=(payload.get("user") or ""),
          client_ip=request.remote_addr,
          req_id=payload.get("token", ""),
          filename=payload.get("filename", ""),
          selected_cnt=len(selected))

# 에러 응답을 돌려줄 때(예: 파일 못 읽음)도 한 줄:
log_event("analyze", client_ip=request.remote_addr,
          filename=getattr(f, "filename", ""), status="error",
          detail="파일 읽기 실패")
```

> `req_id`로 `token`(이미 analyze→mask 사이에 쓰이는 32hex 값)을 그대로 쓰면, 분석과 마스킹을 한 건으로 묶어 추적할 수 있다.

## 7. 이력 조회 방법

- **간단:** `web/logs/usage-YYYY-MM-DD.jsonl` 파일을 직접 열람 / 엑셀로 가져오기.
- **편의(선택):** 관리자용 `/admin/logs` 라우트를 추가해 표로 보여주기. (단, 이 화면 자체에 접근 제한을 두어야 함 — 사번 화이트리스트 또는 운영 PC 전용.)
- **집계:** "이번 달 누가 몇 번 사용" 같은 통계는 JSONL을 pandas로 읽어 `groupby("user")`로 손쉽게 산출.

## 8. 보안·개인정보 주의사항 (필수)

1. **로그에 셀 본문(개인정보) 절대 기록 금지** — 파일명·컬럼명·건수 등 메타데이터만.
2. `web/logs/`는 **깃에 올리지 않는다**(`.gitignore` 추가). 백업·공유 시에도 접근 통제.
3. 파일명 자체가 민감할 수 있음(예: `징계대상자명단.xlsx`) → 보관 폴더 권한 관리.
4. **보관 기간 정책** 수립(예: N개월 후 분리/삭제). 무기한 누적 금지.
5. 사용자명 입력(옵션 B)은 자율 입력이라 신뢰도 한계 → IP/호스트명과 함께 남겨 교차검증.

## 9. 단계별 적용 계획 (권장 순서)

| 단계 | 작업 | 산출물 | 난이도 |
|------|------|--------|--------|
| 1 | `usage_logger.py` 추가 + `/analyze`,`/mask`에 IP 기준 로깅 | JSONL 이력 생성 | ★ |
| 2 | 화면에 사용자명 입력칸 추가(옵션 B) | 사람 단위 식별 | ★★ |
| 3 | `.gitignore`·보관기간 정책·권한 설정 | 운영 정책 | ★ |
| 4 | `/admin/logs` 조회 화면 + 통계 | 관리자 열람 | ★★ |
| 5 | (장기) 사내 인증 연동(옵션 C) | 정확한 신원 | ★★★ |

**1~3단계만 적용해도** "누가(IP+이름) 언제 어떤 파일을 마스킹했는지"가 모두 남아 실무 목표를 충족한다.
